# Оновлення Supabase після code review

Для **наявної бази** відкрийте Supabase → SQL Editor → New query і виконайте весь файл
[`migrations/202610050001_secure_sync.sql`](migrations/202610050001_secure_sync.sql).
Виконайте SQL **до публікації оновлених веб- і мобільного застосунків**: вони використовують нову RPC `save_workout`.

Міграція працює в транзакції, допускає повторний запуск і не видаляє наявні профілі,
вправи, тренування чи підходи. Вона замінює політики доступу п’яти таблиць FitLog,
захищає поля профілю, обмежує RPC та прибирає каскадне видалення історії через каталог вправ.
Видалення вправи з каталогу тепер архівує її; назва й результати в тренуваннях залишаються.

Для **нової бази** виконайте [`../supabase_schema.sql`](../supabase_schema.sql) — він містить
таблиці та ті самі політики/RPC. Для оновлення наявної бази достатньо лише міграції.

Наявні ролі зберігаються. Новим користувачам не надаються права адміністратора за email
або клієнтськими metadata. Якщо потрібно призначити адміністратора, виконайте окремо
в SQL Editor, підставивши потрібний UUID:

```sql
update public.profiles
set role = 'admin', updated_at = now()
where id = 'UUID_КОРИСТУВАЧА'::uuid;
```

Після оновлення перевірте в застосунку: редагування профілю, прив’язку/відв’язку підопічного,
збереження тренування та відображення змін на іншому пристрої. Видалення вправи з каталогу
не повинно прибирати її зі старих тренувань.

## Локальні перевірки

Потрібен Node.js 24 для тестів із вбудованим читанням TypeScript:

```sh
node --test scripts/verify-review-sync.mjs
npm run lint
npm run build
npm --prefix mobile run typecheck
npm --prefix mobile run lint
```

SQL-тест використовує ізольований PostgreSQL через PGlite і не підключається до Supabase:

```sh
npm install --prefix /tmp/fitlog-sql-tests --no-audit --no-fund @electric-sql/pglite
FITLOG_PGLITE_MODULE=/tmp/fitlog-sql-tests/node_modules/@electric-sql/pglite/dist/index.js node scripts/verify-review-sql.mjs
```

Перевіряються повторне застосування міграції, збереження даних, RLS для атлета/тренера/адміна,
заборона самопризначення адміністратора, права анонімного користувача, архівування історії,
атомарний відкат помилки та заборона перенесення чужих ID підходів/вправ між тренуваннями.

Документація: [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security),
[безпека функцій](https://supabase.com/docs/guides/database/functions).

Перевірено під час виправлення: 12 тестів синхронізації, SQL-тести, вебзбірка та TypeScript
обох застосунків пройшли. Мобільний ESLint налаштовано; його повний запуск виявляє
53 помилки й 36 попереджень у наявному коді. Порівняння початкових і змінених файлів
однаковим лінтером не виявило збільшення кількості помилок. Ці окремі зауваження lint
не виправлялись у межах шести проблем review.
